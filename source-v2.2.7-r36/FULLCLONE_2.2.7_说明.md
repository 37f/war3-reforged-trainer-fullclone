# 魔兽争霸 III 重制版修改器 v2.2.7 FullClone R36

本版以原作者 v2.2.7 源码 `2211ad0846fb` 为底，迁入已发布的 v2.2.6 FullClone R34 的累计扩展。适用于 Windows x64 的《魔兽争霸 III》重制版 3.0 系列，具体可用功能取决于游戏构建和地图。完整增量见 [R36 更新记录](R36_CHANGELOG_ZH.md)。

## 大象功能 · AI 托管（仅自己）· 实验性，谨慎操作

进入地图后，打开「大象功能 → 单位与英雄 → AI 托管（仅自己）」。勾选需要的项目，再点击「开启本方 AI 托管」。托管每隔约 1.5 秒分批检查自己拥有的单位。面板显示本次开启以来游戏接受的指令数，以及最近一轮缺少的采集或建造条件。指令数代表下令成功，实际采集量、建造完成和技能命中以游戏为准。

- **自动接敌**。目标搜索范围默认 900，最高可选 25600 游戏单位。只搜索范围内可见的敌人。
- **自动采集**。空闲工人寻找附近可见的匹配金矿，也支持己方闹鬼金矿和缠绕金矿。部分保留标准建造与采集能力的自定义工人也可使用。缺木或找不到金矿时，适用单位会尝试游戏的自动伐木指令，能否采到木材取决于地图和单位。
- **自动建造人口建筑**。托管根据人口余量和原版开局规则安排人口建筑。优先派空闲工人，缺人时调度自己正在普通采集的工人。游戏接受订单后，托管核对目标位置是否出现己方同类建筑，等待期间暂留资源。约 25 秒未确认开工时，下次避开该落点。面板分别统计派工、确认开工和超时，建筑竣工以游戏为准。
- **英雄自动施法**。支持圣光术、凋零缠绕、风暴之锤、闪电链、冰霜新星、暗影突袭、叉状闪电和法力燃烧。英雄须空闲、已学会技能、有足够法力且冷却结束，目标要在技能施法范围内。
- **自动训练单位**。先用原版主基地补齐工人，再用原版兵营训练基础士兵，有条件时混入第二兵种。已有祭坛且没有英雄时尝试训练第一名英雄。启用自动建造后，工人还会尝试补齐首座训练建筑和祭坛，并较早补人口。订单由游戏按地图的实际资源、前置条件和人口限制处理。
- **亡灵对战开局**。自动训练和自动建造同时开启时，参考原版先补侍僧和地穴，再安排通灵塔、祭坛、坟场及二、三本。人口建筑和其他建筑分别等待，资源充足时可错峰施工。适合原版亡灵对战，不代表原生电脑难度或完整对战策略。
- **亡灵开局留工与补人口**。同时启用采集、建造和训练时，托管多准备一名侍僧，优先保留一名空闲侍僧施工。启用集结后，在地穴和祭坛建立后提前安排第二座通灵塔，并优先把食尸鬼补到足够分出采木和战斗两队。
- **不同英雄与祭坛复活**。启用自动训练后，参考原版 `PickMeleeHero` 从本族四名英雄抽选，同一张地图里保持同一顺序，避开已有类型。主基地等级和地图名额限制二、三英雄的训练。阵亡英雄有资格复活时，优先尝试空闲本方祭坛的正常复活订单，由游戏决定费用、耗时和可用性。
- **读取原版 AI 开局规则**。自动训练和自动建造同时开启时，从已连接游戏的本机 CASC 读取 common.ai 和四族 .ai，提取 basic_opening 中可确认的工人目标、首批祭坛、人口建筑和训练建筑顺序。只读提取规则并通过本方托管派单。读不到时沿用内置生产顺序。原版脚本由游戏安装提供。
- **四族进阶生产**。自动训练和自动建造同时开启时，人族会安排铁匠铺、神秘圣地和狮鹫笼，兽族会安排战争磨坊、兽栏和牛头人图腾，暗夜精灵会安排猎手大厅、知识古树和奇美拉栖木。各族按自己的前置条件和资源升级主基地。三族进阶路线经模拟验证，尚待实战对照。
- **自动研究科技**。在己方空闲的原版铁匠铺、战争磨坊、坟场、猎手大厅等建筑中排队研究已匹配的原版升级。游戏负责判断前置条件、资源和研究时间。两次提交至少相隔 12 秒，面板统计已接受的研究指令。
- **优先打野怪**。生命充足的空闲战斗单位在设定距离内优先攻击可见的中立敌对野怪。只勾选打野时，目标限于该类野怪。若也勾选自动接敌，找不到适合的野怪时，仍按自动接敌规则处理。
- **集结与回防**。可选。参考四族本机原版脚本首波出征所需兵力，人族 2、兽族 2、亡灵 6、暗夜精灵 2。基地附近发现可见敌军时优先派空闲战斗单位回防。有健康空闲的英雄和足够兵力时，先把部队集结到英雄附近，然后编队打野或向可见敌军推进。找不到可见敌军时，可以向敌方电脑的地图出生点推进。该选项启用时由编队逻辑接管自动接敌和打野，已有命令优先。亡灵开启自动采集时最多自动派两只食尸鬼伐木。

- **拾取物品和攻击其他目标**。普通物品给最近且有空格的英雄，拾取即用物品允许英雄满包时拾取。单属性书优先分给对应主属性的英雄。常规行动优先最近的合格目标，跳过无敌目标和不可选中的可破坏物。

默认只启用自动接敌。点击「停止本方 AI 托管」会停止新指令，已下达的指令可手动覆盖。换图、断开连接或本地玩家变化后，需要手动开启。自定义采集和建造规则、未列出的技能、扩张和战役任务自动操作暂未支持。编队规则经模拟验证，仍需用实机对照战斗和经济表现。

## 大象功能 · 英雄技能互换

打开「大象功能 → 单位与英雄 → 英雄技能互换」。在游戏里单选第一名英雄，点击「将选中英雄放入候选位 1」，再单选另一名英雄放入候选位 2。自己、友军、敌人和中立阵营均可加入，只需英雄能在游戏里被选中。两个候选位都空时，仍可同时选中两名英雄后直接交换。

可交换第 1～4 槽或整个英雄技能栏，已学等级随技能转移，未学技能保留未学状态。新建技能实例可能重置冷却。点击「还原所有英雄技能」会检查当前地图所有已记录的英雄，无需重新选中。英雄身份或技能栏状态无法核对时，会保留对应记录并报告原因。换图或断开连接后，原地图的候选和还原记录失效。

R36 收录了针对互换和还原时错误使用只读句柄问题的修复。现在开始修改之前会先打开写入句柄，若打开失败，本次操作会在改变技能前停止。

当前实现复用现有选中单位技能接口。遇到重复技能 ID、未能辨认的技能实例或无法核对的英雄身份时，会停止本次互换。测试覆盖了普通及额外槽位、未学习技能、回滚、重复技能拦截和分批还原。实际地图中的技能学习按钮及特殊地图的技能脚本仍需实测。

## 大象功能 · 指定玩家控制和名字切换

在「大象功能 → 目标玩家」从新按钮右侧选择玩家。点击「控制／恢复玩家」切换共享控制，再点一次即可恢复原权限。通过 Ctrl+I+O 也可按游戏选中单位的所属玩家操作。

「玩家名显示」可在游戏中的名字和地图配置名之间切换。下拉框显示编号和对应名称，选中玩家监视使用相同的来源。可确认的队伍名也会显示在队伍编号后。

## 大象功能 · 操作历史与单次撤销

在「大象功能 → 目标玩家」展开「操作历史」。列表收录当前地图最近 30 次有结果的单位转交和外交模板操作，包含面板、快捷键和队伍页拖放。展开一条记录，可查看每个单位的类型 ID 和玩家变化，或查看玩家的模板变化。

- 点「撤销这次操作」，会把可核验的目标恢复到该条记录操作前的状态。单位从玩家 1 给玩家 2，再给玩家 3，撤销第二条后回到玩家 2。
- 同一目标有更新的待撤销记录时，先撤销更新的记录。当前单位身份、归属或外交关系已变化时，对应目标会跳过，原因显示在记录中。
- 「恢复真正原玩家／队伍」仍可恢复首次修改之前的状态。它成功后，相应的旧撤销项会标记为失效。撤销记录只在当前连接的地图会话内有效。

## v2.2.7 原版更新

- 选定玩家的金币、木材、已用人口和人口上限能够持续锁定。某项暂时写入失败时，其余锁定项可以继续处理。
- 失败弹窗显示可识别的具体原因。批量操作列出已处理目标和失败原因，操作后的界面刷新失败会单独提示。
- 存档扫描遇到不可读取的目录时继续扫描其他位置，并列出跳过的目录。

## FullClone 扩展

- **大象功能**。复制归属、阵型大量复制、替换单位、全军补满生命魔法和冻结／恢复、补给包、鼠标位置技能及地面物品聚集。两个 ID 目录的「生成单位」服从大象面板归属选择，`Ctrl+A` 固定复制给自己。
- **队伍与玩家**。切换游戏中名字和地图配置名、监视玩家与队伍、查看或拖放外交模板、恢复单个或全部玩家原队伍。单位转交记录支持恢复选中单位或当前地图内全部已记录单位的原归属。按住玩家卡片时用鼠标滚轮上下移动名单。
- **任务与条件**。手动检测当前地图，读取主支线任务说明和可解析的完成／失败条件。勾选「触发位置」显示可定位地点，点击对应位置可跳转本地视角。能唯一匹配的 JASS 任务显示实时状态，Lua 提供静态解析，实时状态尚未适配。
- **界面**。支持现代深色、白色标签页和 1.0.19 旧式布局。扩展界面可切换中文或英文，地图文字与玩家名称取自游戏或地图数据。

更早的累计改动与快捷键见 [R33 更新记录](R33_CHANGELOG_ZH.md)。

## 从源码构建

需要 Windows x64、Python 3.12 和 Node.js 22。源码包附已构建的前端和本版桥接组件。运行以下命令前，把第一条 `--from-file` 的值换成作者 v2.2.7 原版 EXE 的实际路径。如修改了前端源码，先运行 `npm ci --prefix frontend` 和 `npm run build --prefix frontend` 更新前端产物。

```powershell
python -m pip install -r requirements-build.txt
python tools/prepare_build_baseline_227.py --from-file 'War3ReforgedTrainer-v2.2.7-D0954D1C8846.exe'
python tools/build_fullclone_release_227.py --bridge-image tools/war3_bridge_24268.dll
python tools/build_fullclone_release_227.py --verify-only
```

构建产物 `War3ReforgedTrainer-v2.2.7-FullClone-R36.exe` 位于 `dist-2.2.7-fullclone-r36-verified`。
