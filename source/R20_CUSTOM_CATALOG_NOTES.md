# R20-Test：战役自定义对象 ID 检测

本版在 R19.3-Test 基础上增加离线、只读的战役对象检测。游戏功能、native helper DLL、协议 77 和操作号保持原样。

## 使用方法

1. 打开“物品 ID”“技能 ID”或“单位 ID”页，选择“战役与所选章节”。
2. 点击“选择战役”，选 `.w3n` 文件，例如用户的 `Documents\Warcraft III\Campaigns` 目录内的战役。
3. 从章节下拉框中选择正在玩的章节，然后点击“检测自定义对象”。程序不会自动识别游戏章节；文件检测无需启动游戏。
4. 三个 ID 页共用同一次检测结果。输入 ID、名称、基础 ID 或来源进行搜索；双击一行或点“复制 ID”复制四字符 ID。
5. 点“读取详情”查看所选文件、章节、源 SHA-256、每个对象文件的读取状态和问题。
6. 换章节后旧结果会清空，需要再点检测。想查原版目录，切回“通用目录”。

## 结果含义

- **新增**：作者创建了新 ID，基础 ID 显示其原始模板。
- **原版改动**：作者修改了已有对象，不应当误认为新增对象。
- **战役公共 / 所选章节**：指出定义所在层；同一 ID 的章节字段覆盖战役对应字段，未覆盖的字段继续继承。章节修改战役自定义对象时仍保留其真正的基础 ID。
- **完整读取**：支持的定义文件已读取，不代表该对象在游戏中已经生成或可在其他章节使用。
- **部分读取**：部分文件、名称或对象存在问题；其余成功读取的结果仍显示，详情写明原因。
- **名称回退到通用目录**：文件未提供名称，显示基础目录名称供参考，不冒充作者自定义名称。
- 非 UTF-8 文本或无法解析的字符串会保留证据；不会猜测翻译。原始 ID 不适合现有输入框、或定义冲突时禁止复制成指令 ID。

## 只读范围和限制

只读取 `war3campaign.w3f/.wts/.w3u/.w3t/.w3a` 及所选章节相应 `war3map` 文件。支持对象格式 1、2、3，战役清单格式 1；清单不支持或不存在时尝试档案列表并提示可能不完整。支持编辑器字符串注释和旧对象不透明字段尾值，不通过修改文件修复数据。

不会改写战役、地图或存档，不执行脚本、不导出整套素材，也不调用创建单位、添加物品或添加技能。受保护/损坏档案或缺失清单可能无法完整检测。文件在选择后变化会拒绝旧结果，要求重新选择。

文件读取采用独立随包提供的官方 x64 StormLib v9.40（许可证及来源在 `third_party/StormLib`），不依赖游戏目录中的 DLL；不会把它注入游戏。对象/字符串文件限 32 MiB、单字符串限 1 MiB、单对象文件最多 100000 个对象/1000000 项修改、内层地图限 512 MiB、战役限 8 GiB。60 秒为协作式任务限时，发生超限会明确提示。

## 验证边界

合成嵌套 MPQ、真实战役只读解析、Tk 控件交互和冻结包验证分别记录。游戏内创建这些对象、释放技能和实机与编辑器逐项名称对照，需要额外运行验证，不能由档案解析结果代替。

R19.3-Test 和所有旧版保留，本版 EXE 单独命名 R20-Test。此功能尚未上传 GitHub。
