# v1.0.19 FullClone R18：大象模式四项修复

## 使用哪个程序

运行 `War3ReforgedTrainer-v1.0.19-FullClone-R18.exe`。

目标版本仍为 Warcraft III `2.0.4.23745`。此版本从 R17 独立派生，保留队伍监视及以前的 FullClone 扩展，不覆盖旧 EXE。原作者精确源码参考提交为 `4124cd582ed624eeb85d665484755fa8cae65697`。

## 本次修改

| 快捷键 | 功能 | R18 修改 |
| --- | --- | --- |
| Ctrl+Num1 | 全光环 | 查询地图实际技能等级上限，再设置到 `min(112, 上限)`，不再直接越界设置 112 级 |
| Ctrl+Num2 | 全被动 | 同样检查预设等级上限；允许安全地确保背包存在 |
| Ctrl+Num3 | 获得 6 个神器 | 修复确保 `AInv` 背包被基础组件保护误拦截；保留已有背包，继续使用作者原来的六槽物品替换 |
| Alt+A | 全屏群星陨落 | 修复换命令/地图改范围后结束清理无法退休的状态；不打断新命令，不覆盖地图的新值，避免有效清理之后下一次仍提示忙碌 |

`Num1/Num2/Num3` 指数字小键盘键。先连接游戏，并在全局快捷键及“快捷键功能”中启用相应项目。

### 等级行为

112 现在是这两种预设的请求上限，不是强制实际等级。例如地图的辉煌光环只有 3 级，实际设为 3；地图支持 112 级时才可设为 112。普通手动技能等级设置不改变语义。

### 背包保护

背包属于基础组件。R18 只开放“确保存在”的添加分支，不开放它的删除、重置或等级修改，也不把所有基础技能的检查一起关闭。已有自定义背包不重建；六神器仍要求地图/单位提供六个可用物品槽。

**六神器仍会替换原背包物品，请先存档。** 本次没有更改六个物品 ID 或物品替换规则。

### 群星效果

保留作者原有 `AEsb` 释放路径、全屏范围与 12 秒效果窗口；不是改成创建一个特效模型。

- 如果结束时单位已经接受新命令，不发送 stop 打断新命令。
- 如果群星是本次临时添加的，安全移除该技能，不再恢复即将销毁的范围字段。
- 如果单位本来就有群星，只恢复仍等于本次写入值的范围；地图主动写入第三个值时保留地图值。
- 仍然复核单位与技能的完整身份。对象被回收、真实 stop 失败、原有技能恢复失败等仍报告错误；不通过隐藏弹窗伪装成功。
- 以上行为只针对 `AEsb`，其他法术原有保护策略不改变。

## 为什么不能直接覆盖作者源码

对照后，R17 与作者源码的 27 个相关 Python 函数逻辑相同，相关 C 头文件也相同。背包检查拒绝 `AInv` 与预设直接设置 112 级的问题存在于这条共用路径，不是漏搬了这些功能。

旧日志记录过 `AHab / requested_level=112 / last_error=3221225620`，异常码为 `0xC0000094`；同时有背包错误 13、效果清理错误 13 和后续忙碌错误 170。R18 的离线测试确认了相应代码冲突和清理分支，但不把它们说成用户每一次游戏报错的唯一原因。

## 没有修改的内容

- 读取单位、资源、技能、物品的现有逻辑。
- 原作者操作号、native 绑定签名/哈希资料。
- 复制及归属开关、批量复制、增援、替换、控制、队伍切换/恢复、队伍监视。
- 复活英雄、生命魔法全满、地狱火、英雄等级、三围、金矿、直接胜利等既有扩展。
- 其他大象快捷键。本版不额外修复截图中其他未选定项目。
- 不重新添加游戏速度、名称修改或每秒推进建造等已排除功能。

持久 helper 的 Python/C 协议同步为 `75`。新增技能等级查询只把已有 profile 中的 `BlzGetAbilityIntegerField` 追加到持久 native 名称表末尾，不更改原有名称索引、签名或哈希；原作者按需字段发现路径保持不变。不要混用 R17 的 DLL。

## 游戏内验收步骤

1. 先存档，关闭旧修改器并退出游戏，再重新打开游戏、进入单机地图。
2. 只打开 R18，连接当前游戏，启用对应快捷键。**不要多个修改器同时连接同一进程。** 旧 helper 可能常驻，旧失败 token 不会因更换 EXE 自动消失。
3. 选中英雄，按 `Ctrl+Num1`，确认不弹错误，相关光环技能出现并生效。
4. 先用英雄、再用原来没有背包的普通单位测试 `Ctrl+Num2`，确认可安全添加且不清掉已有背包。
5. 用空背包测试单位按 `Ctrl+Num3`，确认六槽物品生成；有原物品的单位须先备份存档。
6. 按 `Alt+A`，观察群星落下和伤害；效果结束后再按一次，确认不是一直报“忙碌”。再测试释放期间移动单位，确认结束清理不打断后来的命令。
7. 如果仍报错，记录测试的功能、单位 ID、地图、完整弹窗文字，并保留修改器旁 `log/native-helper-*.log` 中对应时间的日志。

**R18 尚未进行实际地图验收。** 自动化/离线通过只证明相应分支、协议、打包与启动，不等于上述游戏效果已经实测通过。验证数字、包校验和自审记录见 `analysis/R18_VERIFICATION.md`。

## 从完整源码重新打包

源码包包含修复后的测试和 helper DLL。使用 Python 3.12.10、Capstone 5.0.7、PyInstaller 6.22.2：

```powershell
python -m pip install capstone==5.0.7 pyinstaller==6.22.2 pytest
python -m pytest -q
python -m PyInstaller --noconfirm --clean '魔兽争霸3重制版修改器.spec'
python analysis/verify-fullclone-package.py
```

修改 C 源码后先用支持 Windows x64 Microsoft SEH 的 LLVM-MinGW 重编译：

```powershell
clang -fms-extensions -fseh-exceptions -shared -O2 -s -Wno-microsoft-goto tools/war3_native_helper.c -o tools/war3_native_helper.dll -luser32 -lkernel32
```

要完整执行真实 C 分派器测试，编译器必须也支持 Microsoft SEH；未找到 `clang` 时相关测试会跳过，不能把跳过当成通过。输出 EXE 为 `dist/War3ReforgedTrainer-v1.0.19-FullClone-R18.exe`。
