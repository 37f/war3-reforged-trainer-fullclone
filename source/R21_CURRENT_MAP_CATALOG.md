# R21 测试版：当前地图 ID 检索使用方法

基于作者 v1.0.19（4124cd5）及现有 FullClone R20 扩展。R21 增加当前运行地图的单位、物品、技能定义检索，保留此前功能、通用目录与战役文件检测。

## 直接读取当前地图

1. 启动 Warcraft III，进入需要查看的地图或战役章节。
2. 关闭其他版本修改器，打开 `War3ReforgedTrainer-v1.0.19-FullClone-R21-Test.exe`，点击“连接/刷新进程”。
3. 打开“单位 ID”“物品 ID”或“技能 ID”页，选择“当前地图”。三个 ID 页共享这一来源和本次读取结果。
4. 点击“读取当前地图 ID”。无需选择战役文件，也无需预先选中单位。
5. 在搜索框输入 ID、名称或基础 ID；双击结果行或点击“复制 ID”可复制四字符 ID。复制操作只放入剪贴板，不会自动创建单位、物品或添加技能。

表格显示 ID、名称、基础 ID、新增/原版改动、数据来源和备注。名称保留地图作者原文，英文界面不会翻译自定义名称。状态栏显示三类定义数及检测时间。

## 三种来源的区别

| 来源 | 读取内容 | 使用条件 |
| --- | --- | --- |
| 通用目录 | 原有离线通用 ID 快照 | 不需要连接游戏 |
| 战役与所选章节 | R20 的战役公共对象与手动选择的章节文件定义 | 选择 `.w3n` 和章节后检测 |
| 当前地图 | 游戏当前已加载的有效自定义/原版改动定义，包括当前章节使用的战役公共对象 | 连接受支持游戏并进入地图 |

“当前地图”包含尚未在场上生成的定义，读取范围不限于所选单位、背包或已学技能。未被地图修改的全部原版对象仍请查通用目录；通用目录不是当前地图的完整原版对象清单。当前地图结果也不包含其他未加载章节。

目录仅说明对象定义存在，不保证将该 ID 用于任意地图的创建、替换或技能操作都有效。

## 换图、菜单和连接

- 返回菜单后，上一章的对象缓存不会被当作当前地图发布。
- 换图、读档、进程/连接变化或会话校验失败时，旧结果与复制权限会失效；进入新地图后重新点击读取。
- 完整退出并重开游戏后，请点击“连接/刷新进程”，再读取当前地图。
- 当 ID 页可见时，修改器会轻量复核地图会话，不会反复全量扫描进程内存。
- 检测结果标为“检测时快照”。若界面暂时无法及时复核，会暂时禁止复制并等待复核；真正检测到会话变化或查询失败后清理旧结果。

## 名称与读取状态

- 显式名称优先；缺少名称字段时沿基础对象继承，最后可回退到通用目录，并在备注说明。
- 名称仍为 `TRIGSTR_*`、编码不明、继承循环、基础对象缺失或多个集合有不同名称时，会保留证据并标为“部分读取”，不会猜测唯一名称。
- 同名候选去重，不同名称候选在详情中标出集合、等级及字段。名称歧义不妨碍复制有效 ID。
- 无法安全放入既有指令输入框的 ID 会禁止直接复制，例如非显示 ASCII 或与十六进制输入语法冲突的 `0xAB`。
- “完整读取”与“部分读取”依据真实结果显示；失败、加载中、菜单和版本不支持不会显示成“0 条、读取成功”。

## 支持与排错

本版当前地图读取只验证了 Warcraft III **2.0.4.23745 x64** 的精确构建；其他构建会拒绝使用未验证的目录布局。此前功能沿用原有适配范围。

- 提示未进入地图：进入地图并等待加载完成后再试。
- 提示地图会话变化：重新读取；如果游戏已完全重启，先重新连接。
- 提示常驻 helper 未就绪：等待连接初始化，点击连接/刷新后重试。
- 提示 helper 协议不匹配：关闭旧版修改器，完整退出游戏后重新启动，再只打开 R21。R21 使用配套协议 78，不能混用旧 DLL。
- 提示超限、超时、格式或指针校验失败：结果不会作为完整目录发布，请保留错误信息供核对，不要修改对象数据来绕过校验。

正式查询接入现有持久 native helper；不新增独立扫描服务、不执行地图脚本、不写入单位/玩家/物品/技能字段，不修改战役文件或存档。不要在 R21 源码中替换其他旧版的 helper DLL。

## 已有功能与交付

原有复制归属开关、复制/大量复制/呼叫增援、玩家队伍与名字监视、原队伍还原、英雄复活、生命魔法全满、替换单位、颜色、地狱火和其他快捷键等继续保留，操作方式沿用此前说明。R21 没有重新加入已移除的游戏速度或建造研究每秒推进功能。
