# R27 任务与条件：多类型地点与对象定位

## 怎么使用

关闭旧版修改器窗口，打开 `War3ReforgedTrainer-v1.0.19-FullClone-R27-Test.exe` 并连接游戏，进入“任务与条件”。R27 沿用 R26 的协议 82、同一份 helper DLL 与独立相机操作 325；本轮已经使用 R26 的游戏不需要为此重开。

展开任务、子目标和条件，可以看到关联的地点／对象。一个可定位地点可直接点击条件行；多个地点分别列出，点击具体位置行或详情中的蓝色链接。灰色“无位置”可以阅读说明，但不能发送相机定位。自动刷新、展开箭头及表头／空白处点击不会移动镜头。

## 新增覆盖

| 类型 | 能从脚本确认时显示的内容 |
| --- | --- |
| 区域 | 进入、离开、通关区域、多个矩形组成的区域、范围触发单位及半径、直接写在事件里的矩形。 |
| 单位／建筑 | 条件或关联动作中的具名击杀、救援、目标命令／对话对象、护送对象、归属变更对象；支持 Reforged 的带皮肤单位构造。 |
| 物品来源 | 按物品 ID 查脚本创建／刷新点；关联死亡回调及显式掉落目标；随机掉落表中的候选物品；随机刷新坐标引用的区域中心。 |
| 商店与交付 | 脚本 `AddItemToStock` 指定商店／NPC 的初始位置；显式上交、交付、使用物品目标点。 |
| 建筑／可破坏物 | 脚本中可定位的可破坏物、单位／中立建筑、占领／归属变更对象，以及明确建造指令的目标坐标。 |
| 镜头／预设点 | 唯一确认的镜头预设目的坐标、固定观察点、传送落点、移动／巡逻等点目标指令的位置线索。 |
| 计时／限时 | 明确计时器回调或同一计时器启动动作关联的刷新点、区域和对象；纯倒计时不编造地点。 |
| 多目标 | 同一条件下分别列出区域、单位、物品来源及其他关联点，逐项点击。 |

地点列表是**脚本关联线索**。原来的完成／失败条件解释与判定语义没有改变。例如，关联动作中有传送或镜头移动，不表示“必须前往这些地点才能完成任务”。

## 坐标来源

每项会标明区域中心、脚本初始位置、刷新点、刷新坐标引用区域、掉落来源、商店售卖位置、交付位置、镜头预设、传送／建造／点目标指令位置等。

**单位只能显示“脚本初始位置，非实时”。** 掉落源也只定位到来源对象的初始位置；实际死亡／掉落位置可能已经变化。物品被发放给某单位或由其持有，会标明“不能据此认定掉落”。随机掉落表显示“候选，非保证掉落”。

物品／单位只按类型 ID 匹配来源时，会标明“按 ID 匹配的脚本来源候选”。同 ID 可以有多个对象，不会自动选其中一个。随机刷新区域只跳转区域中心，具体刷新点未确认。

## 暂时不能确认的情况

- 对象位置由运行时变量、数组／哈希表、复杂循环、随机结果、未解析包装函数决定，且没有唯一静态线索。
- 目标只有单位类型，脚本中没有对应的可定位创建点；或物品只存在于物体编辑器的出售／掉落配置，没有可追踪的 JASS 定义。
- 只给出技能 ID，无法从脚本证明它属于哪件物品；只有任务说明里的自然语言名称，无法确认对应脚本对象。
- 具名单位或镜头预设有冲突定义／多个目的坐标；不能据此猜成唯一当前位置。
- Lua、自建任务系统、动态拼接的函数名、复杂计时器上下文或加密脚本。
- 未由脚本引用、只存放在地图对象二进制数据中的摆放位置。本版没有额外读取这些资源，也没有增加进程／单位读取。

无法定位时保留已识别的对象／ID及“无位置”，灰显不可跳转。单条条件最多保留 256 个关联结果，同类型 ID 最多保留 128 个来源；超限会显示未展开提示。镜头仍受地图剧情、边界、锁定及战争迷雾限制。

## 保留范围

进程／单位读取、当前地图来源校验、任务条件分析器、已有 native 调用、签名表、helper DLL 和独立相机入口均与 R26 一致。R27 仅扩展脚本位置／对象关联与展示。旧版文件保留，本版未上传 GitHub。
