# R24.1：手动检测任务信息

本版保留 R24 的只读任务说明，并按用户要求改为手动检测；R23 的“完成任务”功能仍已删除。任务页只负责检索、分类和解释地图脚本中的信息，不触发任务、不发奖励，也不改任务状态。修改器原有其他功能保留。

## 使用方法

1. 进入地图，启动 `War3ReforgedTrainer-v1.0.19-FullClone-R24.1-Test.exe` 并连接游戏。
2. 打开“任务与条件”页；此时不会自动检测。首次按钮显示“开始检测”，点击后才识别当前章节并读取脚本，无需选中单位。
3. 在左边选择任务，在右边查看任务目标、完成条件和失败条件。搜索框可以按名称、目标或条件文字查找。
4. 想核对原脚本时再勾选“查看脚本依据”。默认不显示调用链、脚本语句和行号。
5. 第一次点击后，按钮改为“重新检测”，即使检测失败、取消或切换选项卡，也不会变回“开始检测”。需要再次检测时由你点击按钮。
6. 切走任务页会取消当前检测并清除旧结果；再切回来不会自动重跑。检测后的来源校验发现换图、断开或过期时，也只清除旧报告并提示点击“重新检测”，不会自行开始新一轮检测。“取消检索”只停止分析。

## 怎么区分主线与支线

| 显示类别 | 分类依据 |
| --- | --- |
| 主线任务 | 地图脚本把该任务标为“必需任务” |
| 支线任务 | 地图脚本把该任务标为“可选任务” |
| 类型未确认 | 标记缺失、动态变化或存在多个候选；不擅自当作主线 |
| 整关失败条件 | 直接让某个玩家失败的脚本规则，与某个任务被标为失败分开显示 |
| 整关胜利条件 | 直接让某个玩家胜利的脚本规则 |

这里的主线／支线沿用地图任务面板的必需／可选语义，不靠任务名和位置猜测剧情重要性。

## 条件说明的读法

- **任务目标**：原地图提供的说明和子目标，清除颜色控制代码并正常换行；保留原文语言，不假称已经机器翻译整篇剧情。
- **触发时机**：例如“有单位死亡时”“有单位进入某区域时”“每隔5秒检查”。
- **还需要**：例如“玩家1的金币不少于500”“某单位已死亡”“某计数不少于3”。玩家序号按界面习惯从1开始。
- **全部满足**：括号里的条件要同时成立；**满足任一项**：其中一个分支成立即可。不同路径是到达该设置点的备选路径。
- **计数／标记**：显示脚本中的计数或真假标记名称，帮助区分不同条件。不凭变量英文名字臆测它具体代表什么；当前值没有实时读取。
- **未找到明确条件**：只表示分析器没有识别到相应规则，不代表没有这个要求，也不代表任务不会失败。
- **尚无法解释／仍有未确认部分**：函数、入口或上下文超出当前支持范围；可勾选脚本依据查看原文，不能将其当成已确认的完整条件。

例如“触发时机：有单位死亡时；还需要：计数‘count’不少于3”，意思是某次单位死亡触发检查时，这个计数必须达到3或以上；它不表示任何单位死亡三次都必定完成，也不表示计数当前已经达到3。

## 地图来源与限制

支持现有自定义战役章节、独立 `.w3m/.w3x` 和可定位到本机资源的官方章节。官方章节明确标为**安装基础脚本分析**：本地松散文件、语言或模组覆盖可能改变实际生效内容，不能把基础脚本当成已经确认的覆盖后脚本。

只看官方基础脚本不要求修改 `Allow Local Files`；程序不更改注册表。读取仍核对当前地图会话、进程身份、安装构建和实际持有的数据文件。版本、来源或脚本语言不受支持时会明确提示，不能用同名文件冒充当前章节。

本版针对 Warcraft III **2.0.4.23745 x64**。Lua、自建任务系统、动态生成文字、复杂回调等不保证完整解析；地图没有标准任务定义时会显示无法识别，不宣称地图没有任务。显示的是脚本信息，**不是任务当前进度或完成率**。
