# 选中玩家名字并入现有队伍监视：简短设计

日期：2026-10-23。状态：已按用户确认的设计实现 R19；验证与限制见 `analysis/R19_VERIFICATION.md`。

## 目的与范围

在 FullClone R18 的“大象功能 → 目标单位”现有队伍监视中，增加实时选中单位所属玩家的实际名字，方便在控制或切换队伍前确认对象。这里显示玩家名字，不是单位显示名称或英雄专有名称；不会增加名称修改功能。

## 方案取舍

- 用户选择：合并到现有监视。共用“监视队伍（每秒刷新）”开关、手动“读取队伍”按钮和串行读取入口，不增加独立开关或第二条轮询任务。
- 未选方案：独立“监视所属玩家”开关。可以分开控制，但增加界面与刷新管理，不符合本次选定的小范围扩展。

## 显示与刷新

- 显示玩家编号、运行中游戏返回的实际玩家名字，以及现有队伍描述；名字不根据编号猜测，也不抄写截图里的固定文本。
- 开启监视后每秒更新；未开启时点击原“读取队伍”也会读取上述信息。
- 支持中文名字以及中立敌对、中立被动；中立槽位仍保留现有标识，不把中立玩家误当普通队伍。
- 玩家名字、玩家编号与队伍必须来自同一选中单位及所属玩家的已验证上下文，避免切换目标后拼接不同玩家的信息。
- 没有选中单位、断开连接或游戏进程变化时，清除旧玩家名字并显示当前状态，不继续显示上一名玩家。
- 如果仅名字为空或无法安全解码，明确显示“名称暂无法读取”；仍可安全获得的当前玩家编号及队伍继续显示，不用旧名字兜底，也不每秒弹错误窗口。

## 实现约束与交付

- 基于已发布 R18；本机旧源码目录已不在，确认后从 GitHub 已核对的 R18 提交恢复独立工作副本。
- 沿用持久 native helper、现有操作锁、后台查询及 UI 主线程刷新方式。只在需要时添加只读名称查询与受限字符串传递，不借机重构其他功能。
- 不改单位读取、归属、玩家控制、队伍切换、首次原状态恢复或外交关系；不改原 native 签名/哈希资料，不移除 R18 的四项修复。
- 独立命名为 R19，保留 R18 EXE 与源码。此次先完成本地源码、EXE、使用说明及校验文件；未经再次要求不上传或改动 GitHub Release。
- 测试覆盖中文/英文、空名、异常字符串、普通/中立玩家、目标切换及取消选择、进程变化、名字读取失败时的降级，以及原队伍监视回归。重新编译 helper、运行完整测试并验证冻结包；没有实际游戏验证时明确标注。

## 留给实现阶段的判断

名称的具体安全传递格式、长度上限及是否需要同步升级 helper 协议，根据恢复的源码及实际字符串接口确定；不猜测游戏对象布局。若现有字符串接口不能安全复用，先补充证据再确定实现，不采用未经验证的指针解引用方案。
