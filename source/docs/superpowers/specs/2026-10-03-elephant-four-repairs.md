# 大象模式四项修复范围

用户要求修复：全光环、全被动、获得 6 个神器、全屏群星陨落。参考是原作者精确源码提交 `4124cd582ed624eeb85d665484755fa8cae65697`。

## 已查证

- R17 的相关 Python 入口与作者源码逻辑相同；技能操作、效果生命周期、物品批处理等相关 C 头文件逻辑也相同。不能把此次错误归因于遗漏搬运。
- 全被动和六神器先添加 `AInv`，但共用技能检查明确拒绝 `AInv` 基础组件。
- 全光环和部分被动预设直接设置等级 `112`，没有检查地图提供的技能等级数量。日志有 `AHab / requested_level=112 / last_error=3221225620`，异常码为 `0xC0000094`。具体哪一次引擎调用抛出异常仍需专项验证。
- 效果日志中出现清理错误 `13` 和后续忙碌错误 `170`；当前清理流程在单位换了命令或技能范围被地图改动后拒绝清理并保留 token。这是群星的排查线索，不等同于已证明用户每次报错的具体分支。

## 已确认并实施的修复行为

1. 只允许添加入口安全地确保背包存在；不允许绕过基础组件的删除、重置、等级修改限制。
2. 全光环/全被动的预设等级先读取地图实际等级上限，设置 `min(112, 上限)`；普通手动技能等级修改保持严格语义。
3. 只调整 `AEsb` 群星效果的结束清理：不打断用户后来下达的新命令；临时添加的技能直接安全移除；原有技能仅恢复仍属于本次操作的范围改动，地图主动写入的第三值不覆盖。单位和技能身份失效仍然报错，不隐藏异常。
4. 保留 R17 队伍监视和全部既有扩展、读取、原作者操作号/绑定资料；不增加速度或每秒推进建造等已排除功能。

## 交付与验收

- 独立 R18 EXE、源码 ZIP、说明、校验文件；不覆盖 R17。
- 先用实际 C 分派器的离线回归证明修复，再验证打包源码/DLL 一致性及离线启动。
- 游戏内验收需单独验证四个快捷键以及群星连续使用；离线测试通过不算游戏实测通过。
