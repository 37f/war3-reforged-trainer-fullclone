# R28-Test：任务触发前定位

本版在 R27 多类型条件定位基础上，增加任务创建／发现入口的静态位置线索。原扩展功能保留，R27 及更早 EXE 不覆盖。本版没有上传 GitHub。

## 使用方法

1. 进入战役章节或地图，运行 `War3ReforgedTrainer-v1.0.19-FullClone-R28-Test.exe` 并连接游戏。
2. 打开“任务与条件”，等待现有脚本检索完成；需要时点击“重新检索”。
3. 展开主线或支线任务。每个任务都新增“触发前位置”分组。未完成或状态未确认时，该分组优先展示；已经完成／失败时，原条件优先展示，触发前线索仍可查阅。
4. 有多个地点时，逐条列出。点击具体位置行、选中后按 Enter，或点击右侧详情中的蓝色地点，沿用既有相机入口移动本地视角。只选择一个包含多个地点的任务／分组时，会提示选择具体地点。
5. 灰色“无位置”不调用相机。自动刷新、任务状态同步和恢复选中行都不会自动移动视角。

**接取／发现状态没有读取。** 既有接口只返回完成、失败标记，不能区分“对象已创建但隐藏”“已接取但未完成”“尚未创建”等情况。本版不改该接口，因此对未完成／状态未确认任务优先提供触发前线索，同时保留原条件及子目标；不会把这些状态直接认定为“未触发”。

## 触发前位置来源

- 延迟创建任务：追踪创建该任务的事件入口、条件和明确调用链，不要求已有运行时任务句柄。
- 提前创建的隐藏任务：追踪 `QuestSetDiscovered(..., true)` 或可唯一关联任务的 BJ 包装入口。显式 `false` 不当作接取入口。
- 进入／离开区域、单位事件和范围事件：显示区域中心、范围，或对应对象的脚本初始位置。
- 触发条件中的单位／NPC：例如订单目标与指定 NPC 相等、某个单位死亡／救援等，显示可解析的对象初始位置。
- 触发物品：复用 R27 的 ID 来源关联，包括脚本刷新、掉落来源、商店或 NPC 库存等。随机来源仍标为候选，持有者不等于掉落证明。
- 明确的前置事件：追踪直接函数调用、显式 TriggerExecute、计时回调；关联此前的固定传送落点、观察点、建造位置。对话框事件可回溯明确显示该对话框的事件地点。
- 条件或入口引用的镜头预设、可破坏物、建筑、固定坐标等，复用已有解析。

每个地点注明来源。单位显示“脚本初始位置，非实时”；不会把单位当前所在位置、实际掉落位置或动态随机刷新位置说成已确认。

## 保留范围与限制

没有修改读取进程、单位参数、原任务条件分析器、native 参数表、既有调用逻辑、helper DLL、协议 82 或独立相机操作 325。没有执行接取／完成任务，没有移动或创建单位，没有修改任务条件。

以下情形可能显示“无位置”或只列出部分静态候选：

- Lua、加密或无法确认来源的脚本；任务定义本身未被现有分析器识别。
- 动态数组、哈希表、缓存、运行时创建对象、不能唯一关联的任务别名或动态回调。
- 只有物体编辑器／地图二进制数据中的地点；脚本中没有对应坐标。
- 纯计时、纯变量判断、抽象全局事件，没有可关联对象或区域。
- 复杂对话系统、触发器动态启停、跨章节缓存、未显式连接的前置流程。
- 同 ID 多来源、随机来源，只能给出候选；超出关联数量／深度／时间上限的部分不会猜坐标。

“触发前脚本线索”表示该地点与创建／发现入口有关，不代表到达后一定立即接取任务；其他布尔前置条件、剧情状态和计数要求仍以原条件解释及地图实际脚本为准。

本版通过源代码测试、真实章节文件只读样本和冻结包检查。本轮未执行游戏中的新触发入口或逐项实测跳转；沿用相机入口此前在 R26 中经游戏实测并由用户确认，DLL 字节未改变。
