# v2.2.3 FullClone R31.13-Test 使用说明

本版以你提供的 **v2.2.3 / e4930f5e0739 源码**为基础，接回此前 R30 累计扩展。原作者的新界面、3.0 扩展背包、装备、天赋、字段编辑、存档提取、地图脚本工具及原有快捷键保留。

本版程序为 `War3ReforgedTrainer-v2.2.3-FullClone-R31.13-Test.exe`，文件版本 `2.2.3.323`。这是独立测试版，不覆盖作者的 `War3ReforgedTrainer-v2.2.3-B8CE00485658.exe`。

本版在「队伍与玩家」增加 **查看或修改外交模板** 分组：可按大象“加入队伍”套用的外交模板查看玩家，表格和详情也会显示该模板。原生队伍仍按本次地图第一次确认的编号分组，加入队伍只改外交、不改原生队伍号。R31.10 的分组固定、R31.9 的分组标题、R31.8 的共享控制修复均保留。详情见同目录 `R31_13_更新说明.md`。

## R31.13 新增操作

### 恢复所有玩家真正原队伍

- 大象功能“目标玩家”中点击 **恢复所有玩家真正原队伍**；或在“队伍与玩家”中将分组方式改为 **查看或修改外交模板**，点击同名按钮。两处调用同一功能，不需要选中单位。
- 恢复范围为本次游戏地图、当前修改器连接中记录过首次切换前关系的全部玩家；没被本修改器修改过的玩家不写入。没有记录时提示“本次地图没有可恢复的原队伍记录”。
- 恢复的是此前“加入队伍”修改的双向外交关系；原生队伍编号仍保持原有逻辑，不另改编号，也不移动单位归属。
- 记录在第一次修改之前保存，反复换队不覆盖。恢复按首次记录的逆序执行，避免玩家之间的关系被后来的快照覆盖；已经单独恢复过的记录也参与校正。手动控制/恢复功能的共享控制权限保持当前值。
- 写入前核对全部记录和玩家身份。执行中若失败，停止并报告已恢复数量，保留原记录；不自动重试或猜测缺失的原队伍。
- 重开修改器、重新连接、换地图后，不能恢复上一连接中未保存的旧记录。若曾在另一个修改器中改过外交，本程序只能记录它自己第一次修改之前的状态。

### 记忆模式

- “队伍与玩家”和“任务与条件”工具栏各有 **记忆模式**，默认勾选。切换其他页再返回时保留结果、当前选择、筛选、勾选和滚动位置；三种界面布局共用。
- “每秒监视玩家名字和队伍”的勾选，以及下面的单位监视勾选，也会在本窗口切页时保留。离开相应页面时暂停定时读取，返回后继续。
- 页面记忆仅在本次窗口内有效；不会把游戏指针、玩家快照或任务证据写入硬盘。玩家页返回时只做当前地图校验，不自动重新扫描目录；地图或连接变化时清除旧结果，要求重新读取。
- 任务页返回时继续读取和校验已有任务状态，不自动开始脚本分析；仍需点击“开始检测／重新检测”才发起检测。换图后旧结果不再提供可用跳转。
- 取消记忆模式后，离开该页再返回会重置本页选择和勾选；后端已生成的任务结果仍可读取，不会删除分析报告。

### 每5秒监视单位状态

1. 连接游戏，在游戏内选中单位。
2. 打开 **选中单位** 页，勾选 **每5秒监视单位状态**。默认关闭，勾选后每隔5秒按现有“读取全部单位”的方式读取当前选择，并更新生命、魔法、坐标及字段表；在游戏中换选单位后，下次刷新跟随当前选择。
3. 取消勾选停止；切到其他页暂停，返回该页继续。断开或重新连接后关闭监视，需重新勾选。

定时读取不叠加请求；输入框正在编辑或写入操作未完成时跳过本轮，避免覆盖正在填写的值。没有读取到单位时清空旧单位显示；读取失败后停止监视，避免持续弹窗。此功能只读，不锁定生命魔法、不执行修改。

### 本版验证范围

自动化覆盖批量恢复顺序、重复换队、共享控制保留、身份/地图变化拒绝写入、部分失败停止，以及真实浏览器三种布局的页面记忆和监视交互。浏览器使用模拟RPC，未向当前游戏执行恢复或写入；这不等同于本地图的游戏内验收。

- 旧版布局收起底部游戏风格命令台，当前按钮、全局快捷键和后端保持共用。新增任务、地图检索、物品聚集等功能仍可使用。

## 开始使用

1. 保存游戏进度，关闭其他修改器。
2. 进入地图后打开本版程序并连接游戏。
3. 在“大象 → 经典功能”上方找到 **FullClone 扩展**。原作者的经典功能仍在该页下方。
4. 使用游戏内快捷键时，开启全局快捷键总开关，在“大象 → 全局快捷键”勾选相应功能。
5. 同一时间只运行一份修改器。原队伍、控制状态和碰撞切换记录只属于当前地图、当前连接；重新连接、切图或退出程序后不跨地图恢复旧指针。

## 队伍与玩家（R31.7 新增）

1. 连接游戏，在新版界面打开 **战况 → 队伍与玩家**；两种旧版界面直接点击顶部 **队伍与玩家**。
2. 也可从 **大象功能 → 目标玩家／目标单位** 点击 **查看队伍与全部玩家**。
3. 点击 **读取／刷新玩家信息**，显示当前地图的全部玩家槽位；打开页面本身不启动扫描。
4. 左侧 **地图初始势力** 对应编辑器里的“英雄／地底居民”等分组，展开后列出各玩家。点击分组名筛选右侧，点击成员显示详情；点击 **查看全部玩家** 取消分组筛选。
5. 切换 **原生队伍（读取时）** 查看按本次地图第一次确认的原生队伍号分组的成员。普通队伍从1开始显示，原始 -1 标记为“未分配普通队伍”，特殊中立槽位单列。分组标题会带上只含本队成员的地图势力名，人数写成“N 个玩家”；势力同时含有别队活动玩家时只显示队伍编号，不做猜测。加入队伍后再次读取，仍使用加入前记下的队伍号，不会把选中玩家分到另一组。本版使用独立的指定玩家只读查询，不要求当前选择单位；未确认的返回不会当成队伍1。
6. 切换 **查看或修改外交模板** 查看大象“加入队伍”套用的模板分组，例如“队伍 1”“中立敌对”。尚未套用或已恢复原队伍的活动玩家按原队伍分组，自己也显示在对应队伍。可以拖动左侧玩家框至目标队伍并修改外交模板，详见下方R31.13说明。
7. 表格列出槽位、名字、颜色、种族、控制者、槽位状态、原生队伍、当前外交模板和地图初始势力。支持搜索及隐藏空槽／已离开玩家。当前3.0游戏实际返回28个槽位，含玩家25～28的特殊中立槽位。
8. 点击名字或左侧成员，下方显示当前外交模板，以及固定开始点、开始点坐标、界面皮肤等 **地图初始配置（非实时）**。旧格式没有HUD字段时明确显示未确认。
8. 勾选 **每5秒监视** 后按间隔重新读取。扫描未结束时不叠加下一轮；手动点击 **重新读取地图配置** 可重新核对来源。

**来源区别：** 玩家名称优先使用既有实时读取函数；若实时结构校验或内存页读取未通过，则显示带来源标记的“地图配置名（非实时）”。中立名字为空时显示中立槽位标识。绝不把初始名称说成游戏当前改名后的名称。颜色、种族、控制者、槽位状态和开始点索引是游戏读取值；固定开始点、编辑器势力名、界面皮肤和初始坐标来自当前章节 `war3map.w3i` 及文字表。

**队伍区别：** 大象“加入队伍”套用外交关系模板；“当前外交模板”只展示这次套用记录，“原生队伍”仍用加入前记下的编号，二者分开。中立的原始队伍值即使为0，也不列入普通队伍1。

**操作边界：** 玩家属性与地图配置只读；只有“查看或修改外交模板”内的拖放会修改外交关系，不改名、不设置颜色、不执行任务。当前章节来源沿用已有任务来源校验；来源无法确认或配置格式未知时，仍显示能确认的游戏字段，其余明确未确认。支持现有已适配的3.0配置格式（含39）；新格式、新游戏小版本或保护内存页可能导致部分字段未确认。切图后的新查询会核对来源；未启用监视时页面保留上次读取结果和时间，请在切图后刷新。连接/PID变化或整轮读取失败时清除旧表，避免混用。截图样本和自动化检查不能代替每张地图的人工验收。

## 复制、创建与归属

“启用面板复制归属”默认关闭。

| 操作 | 关闭开关 | 开启开关 |
| --- | --- | --- |
| 面板复制、Ctrl+B | 保留源单位归属 | 按“给自己 / 给选中单位所属玩家 / 给指定玩家”选择 |
| 大量复制、Ctrl+N | 保留源单位归属 | 按同一面板选择 |
| 呼叫增援、Ctrl+K | 作者原来的本地玩家创建逻辑 | 按同一面板选择 |

| Ctrl+A 复制给自己 | 始终给自己 | 始终给自己 |

指定玩家下拉列表包含玩家1～24、中立敌对（玩家25）、中立被动（玩家28）。普通玩家槽位在地图中未启用时，提示“没有所属玩家”。

复制不要求预先读取单位。完整复制复用作者 **3.0 完整状态事务**，保留该版本对技能、英雄成长、普通背包、扩展背包、装备位置和天赋记录的处理。地图异常技能仍可能被作者逻辑跳过；跳过会提示，不承诺所有地图技能逐项无损。

给指定玩家复制使用独立包装入口，在第一次创建副本时就使用目标归属，不先创建给自己再转交。批量操作失败时不会自动重放，也不删除前面已经成功创建的副本。

## 玩家、控制与队伍

| 功能 | 操作 |
| --- | --- |
| 把选中单位交给指定玩家 | 选择“目标玩家”，按 Ctrl+I+U，或点击对应按钮 |
| 控制 / 恢复选中单位所属玩家 | Ctrl+I+O，再次按下恢复；不转移单位归属 |
| 应用队伍外交模板 | 选中该玩家任意单位，选择队伍1～12或两个中立模板，按 Ctrl+F1 |
| 恢复真正原队伍关系 | 点击“恢复真正原队伍” |
| 查看玩家名字与队伍 | 点击“读取选中玩家与队伍”，或勾选“每秒监视玩家名字和队伍” |

队伍功能与旧扩展一样，套用**外交关系模板**。原生队伍编号单独显示，不把中立槽位或原生 `-1` 猜成普通队伍。连续切换多个模板后，恢复仍使用本次地图第一次切换前保存的全部双向联盟标志。控制状态也在第一次写入前记录，部分写入失败时保留恢复依据。

R31.8 起，队伍模板只写除共享控制以外的外交标志：加入队伍和恢复原队伍两条路径都保留调用前的两个共享控制位（`ALLIANCE_SHARED_CONTROL` 与 `ALLIANCE_SHARED_ADVANCED_CONTROL`），不会因为套用模板而让新队友获得你单位的控制权，也不会让你自动获得对方的控制权。控制权仍然只用「控制 / 恢复选中单位所属玩家」单独切换。

监视显示玩家编号、实际名字及队伍。名字读取失败不会阻断编号和队伍；中立敌对、被动为空名字时省略“名称暂无法读取”。选中单位在读取中变化时，迟到结果不继续显示。

| 快捷键 / 功能 | 用法 |

“自定义”未勾选时，快捷键数值框为灰色禁用状态，仍能看见原默认数字。原面板的“设置英雄等级”按钮继续使用面板输入值。

替换沿用R30语义：保留归属、位置、朝向及生命/魔法比例、资源余量；英雄替换为英雄时保留经验，转移原六格背包中的物品实例。荒芜金矿使用专用创建入口。创建或物品转移失败时，在移除原单位前尝试退回已转移的物品。

替换属于创建新实例并移除原实例，不是只改显示模型；不承诺保留原单位的脚本引用、任务绑定及3.0扩展背包、装备或天赋。地图脚本可能对新建、移除单位作出反应。完整复制与替换单位是不同的操作。

## 地狱火、物品聚集与胜利

- **Ctrl+F2**：在鼠标地面位置真实施放 `AUin`，归自己。使用不可见、不可选的临时施法载体，随后清理；不使用显示步兵的定时生命倒计时。运行中的游戏可继续播放技能自己的陨石、落地、眩晕与召唤流程；不要在暂停状态执行施法。
- **Alt+F2**：将当前地图可见、存活、未被单位持有的地面物品聚集到鼠标位置。移动原实例，不重建、不修改数量；背包、扩展背包、商店库存与隐藏物品不参与。先固定本次物品集合，之后才移动。部分失败不自动重放、不猜测回滚。
- **Alt+B**：仅使用作者原来的胜利秘籍 `allyourbasearebelongtous`。已移除扩展面板的胜利方式选择及“玩家直接胜利”执行入口。Alt+B沿用作者的默认未勾选状态，需在全局快捷键列表中勾选后使用。

本版这些操作尚需游戏内逐项验收。当前验证只读核对了接口和过滤流程，没有执行复制、换队伍、施法或聚集。

## 自定义 ID：读取当前地图

进入“典籍 → 自定义地图数据”，点击 **读取当前地图**。也保留作者的选择战役、地图文件方式。

当前图入口复用作者的文件目录解析器，自动定位本地档案；战役只保留当前章节和战役共用数据，支持单位、技能、物品和科技。结果来自静态物编和数据表，脚本运行后临时改写的实例值不在这个目录里。

切图或连接变化会使当前图结果失效，需重新读取。通用 ID 检索、3.0 装备和英雄技能目录仍使用作者新版原目录。

## Lua任务检索（R31.7新增）

当前地图为Lua时，点击“开始检测/重新检测”也会自动查找实际地图/战役章节并做静态分析。没有执行Lua代码、require、load、触发器或任务完成入口。

- 覆盖可解析的标准任务/BJ创建、任务名、原说明、子目标、主线/支线标记、命名回调、分支和可追溯完成/失败条件。复用原有列表与条件结构。
- 区域、脚本初始单位/物品/建筑和镜头等地点沿用原位置解析；必须勾选“触发位置”才显示。有位置可用已存在的独立相机入口；本次没有实测点击跳转，也没有新增相机native。
- Lua实时变量尚未绑定，任务状态显示“状态未确认”。不将Lua宿主当JASS VM，不使用JASS符号表或JASS状态查询。
- 动态调用、匿名闭包、复杂表/方法、for迭代器、分支内局部作用域和and/or值选择等暂不展开。遇到不支持内容，整个函数标为未展开；不会丢掉其判断后把内部完成调用当作无条件。
- 对地图覆盖的StringIdentity，只能展示基础WTS的候选文字，并明确标注“最终文字未确认”；不执行该包装函数或猜测运行时本地化结果。当前战役基础WTS中的文字按原文展示。
- 本章实际只读核对：UndeadRE01.w3x，20个任务（9主线、11支线），51个位置候选。分类/地点来自脚本，不表示已触发或已完成，不表示所有复杂条件都已完整解析。

## 任务与条件

任务结果超过可视区域时，可将鼠标放在任务列表或右侧条件说明上，用滚轮上下浏览整个任务页，也可拖动右侧滚动条。状态轮询不会主动重置阅读位置。

1. 打开“典籍 → 任务与条件”。打开页面本身不开始检测。
2. 首次点击 **开始检测**；此后按钮为 **重新检测**。
3. 选择主线或支线，查看地图原任务说明、子目标以及易读的完成、失败条件。未能解析的部分单独列出。
4. 默认不显示区域。勾选 **触发位置** 后才显示触发前位置、条件地点及坐标按钮。
5. 多地点分别点击；只有一个地点的任务，在勾选位置后点击条目可直接定位。没有地点显示“无位置”，不可点击。
6. 位置包括能静态确认的区域、单位、物品掉落或刷新来源、商店/NPC、建筑、可破坏物、镜头预设和计时关联点。单位初始坐标标明“脚本初始位置，非实时”。
7. 完成、失败状态在有可靠来源和唯一标量任务变量时每秒同步；不能唯一匹配则显示“状态未确认”，不凭标题或原说明猜测。

独立相机入口只移动本地视角。没有任何“直接完成任务”、触发任务奖励或执行地图脚本的功能。

**目前自动地图来源与任务变量布局仅对本次核对的精确游戏版本 `3.0.1.24371` 接入。**其他小版本可以先使用指定文件分析。Lua支持上述静态子集；自建任务系统、动态数组任务和无法唯一绑定的任务明确提示未确认。

本机的 `Allow Local Files` 保持原值1，没有改注册表。官方安装包基础脚本可以阅读，但本地覆盖优先级未确认时，不能据此声称实时状态已经绑定；相应状态显示“状态未确认”。

## R31.13：查看或修改外交模板

在“队伍与玩家”中点击“读取／刷新玩家信息”，将“分组方式”改为“查看或修改外交模板”。左侧队伍显示为“森林巡逻队（队伍 1）（4 个玩家）”这样的格式。

- 玩家没有套用模板，或已经恢复原队伍时，按原队伍显示，不再混放到“未套用外交模板”。
- 自己的玩家也在对应队伍中，名字旁显示“自己”。队伍名称固定来自原成员对应的地图势力，不因成员移动改名；人数按当前显示成员更新。
- 把左侧玩家框拖入另一队伍的标题或框内，松开即可修改该玩家的外交模板。目标框会高亮。可拖动自己、其他活动普通玩家、中立敌对或中立被动，不需要切换游戏里的选中单位。
- 成功后重新读取并刷新分组及人数。同一队伍内拖动不执行；操作未完成时不重复提交。游戏断开、换图或数据失效时拒绝，需重新读取。
- 仍然只调整外交关系，不修改原生队伍编号、地图文件、单位归属或共享控制权限。原生队伍和地图初始势力两个查看方式继续保留。
- 所有成员离开后，原队伍仍作为空的拖放目标保留。读取不到或不能唯一对应的队伍原名显示“未读取队伍名”；队伍编号不能确认的分组不接受拖放，不凭地图势力顺序猜测编号。
- 中立敌对和中立被动使用对应特殊槽位模板，不编造普通队伍13、14。其他特殊中立槽位与空槽只展示，不能拖放修改。

本次加入了独立的“指定玩家外交查询/应用”扩展操作19/20；原有操作号0～18、native函数槽位和参数ABI保留。查询不要求游戏选择单位；应用前核对目标玩家、连接和地图代次，控制位在Python与原生入口双重检查。现有大象“加入队伍”“恢复真正原队伍”“控制/恢复选中玩家”继续使用原路径和恢复记录。

首次使用此版本前，请关闭旧修改器，并完整退出后重新启动游戏，再打开R31.13连接，以加载新助手。R31.11的EXE和源码包保留，不覆盖。
