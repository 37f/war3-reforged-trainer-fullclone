# v2.2.3 FullClone R31.8-Test 更新说明

本版修复 R31.7 反馈的“加入队伍后共享控制权限被改动”的问题，其余行为与 R31.7 相同。

## 问题原因

“加入队伍”通过复制参考玩家（该队伍的第一个成员）的整套双向联盟标志来套用外交模板。这套标志里包含两个共享控制位：

- `ALLIANCE_SHARED_CONTROL`（标志 6）
- `ALLIANCE_SHARED_ADVANCED_CONTROL`（标志 7）

因此加入队伍后，新队伍成员会自动获得对你单位的控制权限，你也会自动获得对方单位的控制权限；“恢复真正原队伍”同样会写入这两个位，从而覆盖加入后手动切换过的控制状态。

## 修复内容

- 队伍外交模板现在只写除标志 6、7 以外的外交标志（0～5、8、9）。
- 加入队伍与恢复原队伍两条路径都保留调用前的当前共享控制位，控制权不再随模板变化。
- 控制权仍只由「控制 / 恢复选中单位所属玩家」（Ctrl+I+O）单独切换，双向记录和失败恢复逻辑不变。
- 未改动：原生队伍编号读取、玩家目录显示、“队伍与玩家”只读页面、其他外交标志、native 操作号 8/9/10、桌面协议与生产桥接 DLL。

## 已知保留行为

- 选中的玩家在“队伍与玩家”页面仍按其原生队伍分组显示。加入队伍只套用外交关系模板，不改变原生队伍编号，因此该页面不会把玩家重新分组。这是 R31.7 已确认保留的显示行为。
- 除共享控制以外的外交标志（共享视野、共享经验等）仍按所选模板整体套用，这是队伍模板本身的功能。

## 验证记录

- 204 项 Python 测试通过，其中新增 3 项：加入队伍不复制参考玩家的共享控制、恢复原队伍保留加入后手动切换的控制位、无参考玩家的兜底外交模板保留控制位。
- 既有测试 `test_first_team_snapshot_survives_many_switches_and_restore`、控制切换失败恢复、native 夹具测试全部保持通过。
- 冻结界面检查结果随包附带；本版未在游戏内执行写入操作，仍需用户实机验收。
- 本版为独立 Test 版，未覆盖作者原程序，也未上传 GitHub。
