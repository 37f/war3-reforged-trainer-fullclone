# R27 多类型任务位置关联

基线：R26 `f84e389`。任务范围：补展示引用及空间来源，不改条件判定、进程／单位读取或相机/native 逻辑。

## 核对后的数据入口

既有 `ConditionPath` 包含 guard、events、callers、evidence 和 variables；`QuestReport.snapshot` 已有经原来源逻辑读取的 JASS。R26 只查看 guard/events 中具名单位、矩形、地点变量，未使用大部分动作及计数来源证据。

R27 在同一位置解析层使用已解析脚本建立有界的调用引用索引，跟随明确函数实参、直线／同分支局部赋值、触发器回调和显式计时器关联。仍然复用原条件路径，未重新执行／判定条件。

## 实现文件

- `war3_quest_locations.py`：对象与来源描述、可定位标记；物品／可破坏物／带皮肤单位构造、显式包装函数返回与局部别名。单位初始坐标明确标“非实时”。
- `war3_quest_location_links.py`：独立的只读脚本关联索引；掉落、商店、交付、镜头、传送、建造、移动及计时关联。没有进程接口或 native 调用。
- `war3_quest_text.py`：展示更多事件／对象名称；原 guard 与条件组合不变。
- `war3_quest_ui.py`：无坐标对象也可读，但灰显且不会调用相机。有效地点沿用 R26 跳转。
- 相关测试与 R27 独立 spec／版本信息／包校验／使用说明。

## 防止错误关联

- 不遍历整段任务注册初始化并把其他任务区域混入当前任务。
- 包装函数的相反分支不因同属一个函数而混入当前状态路径。
- 地图自己定义的同名包装函数按实际函数体追踪，不能凭熟悉的函数名认定有掉落、商店或镜头动作。
- 持有物品不等于掉落；随机候选不等于实际掉落；按 ID 匹配不等于唯一实例。
- 运行时 `GetUnitX/Y/Loc` 不会直接替换成初始坐标。只有明确的来源关系才单列该对象的初始位置，并说明不是实际死亡／刷新坐标。
- 固定坐标不能确认时不生成可点击的 `(0,0)`；保留对象与无位置说明。
- 调用深度、帧数、来源数和结果数均有上限；没有任意执行脚本、全堆扫描或额外单位读取。

## 验证边界

新增测试覆盖用户列出的八类场景、未知对象不可跳转、关联初始化隔离、包装函数分支隔离和同名函数不猜语义。

对用户《雷克萨之书》`K-ValleyOfTrial.w3x` 做只读文件样本分析，位置关联索引构造约 0.5 秒。确认能增加任务相关对象／剧情点及物品来源；百科说明没有条件地点时仍为无位置。这是实际战役文件解析，不声称逐项看到了游戏内对象。

本版 helper DLL、相机入口和主程序读取部分与 R26 完全一致；R26 的独立相机在本会话已经实际验证并由用户确认。本轮不重复操作游戏镜头。最终检查数及包哈希见交付文件。
