## 已观察结构：限该精确游戏构建

此处为调查发现的 RVA/相对结构，不承诺其他版本可用，不允许将某次运行堆地址写入产品。

上下文入口 RVA `0x30d360` 通过参数 13 得到对象数据上下文；当前 typed getter 汇编使用 `qword(context+0x20)` 作为状态。单位/物品/技能管理器分别在该状态的 `+0x230/+0x238/+0x338`。

相关 getter RVA 为 `0x11ad500/0x11ad3f0/0x11ad0c0`。它们在管理器未初始化时有分配路径，故正式只读目录操作应读取已存在的指针，不能借调用 getter 触发创建。

管理器 vtable RVA 分别 `0x242c410/0x242c470/0x242c4d0`；`+0x25a8` 为类型 0/1/4，`+0x25b0` 为原始定义对象，`+0x25b8` 是字段元数据而不是对象定义。

原始定义对象：

| 偏移 | 含义 |
| --- | --- |
| `+0x00` | vtable |
| `+0x08` DWORD / `+0x10` QWORD / `+0x18` DWORD | 原版改动数组数量 / 指针 / 容量 |
| `+0x20` DWORD / `+0x28` QWORD / `+0x30` DWORD | 新增数组数量 / 指针 / 容量 |

数组记录跨度 `0x28`：原始 rawcode 字节 `+0`、新 rawcode 字节 `+4`、字段集合 hash 表桶数 `+8`、桶指针 `+0x10`、集合数 `+0x18`。rawcode 是字面四字节，不要把外部表示的大端整数直接套用到全部结构。

集合 hash node 的 `+0` 是 next，`+8` DWORD 是集合 key；`+0x10` DWORD / `+0x18` QWORD / `+0x20` DWORD 是修改记录向量数量/指针/容量。修改记录跨度 `0x48`：field 四字节 `+0`，type `+4`，level `+8`，data pointer `+0xc`，数值区域 `+0x14`，字符串指针/长度/容量在 `+0x18/+0x20/+0x28`，内联字符串区域 `+0x30`，尾标识 `+0x40`。本次只将名称字段视为最终核对范围，其他数值字段仍属辅助探测结果。
