## 有代码与结构检查的元数据路径

`GetGameDifficulty` 的实际代码尾部在 RVA `0xc50003`：

- 读取 `q(image+0x2b59964)`，与常量 `0x363abbfd3defaec9`、`q(image+0x2bd7bc8)` 异或取得世界对象。
- 世界对象 `+0x2670` 为配置对象；代码随后读取难度字段。这里只读世界／配置元数据，不调用设置接口。
- 该 62 字节代码的 FNV-64 为 `a13bc516c90ae996`。

配置对象 `+0x40` 的字符串容器、`+0x50` 的字符串条目、条目 `+0x38` 的 UTF-8 指针给出当前地图资源路径。结构类型校验使用已观察 vtable RVA：世界 `0x23d0690`，配置 `0x23d0508`，字符串容器 `0x21dea60`，条目 `0x21de9b0`。

`SetCampaignMenuRaceEx/SetCampaignAvailable` 使用 RVA `0x9dde50` 的战役判定：读取 `image+0x2bd7a10` 的当前战役路径，并检查世界对象 `+0x304f`。该 39 字节函数 FNV-64 为 `9afa250dca103fd3`。非战役模式忽略可能残留的战役字符串。

PE 校验包括时间戳 `0x69e54471`、SizeOfImage `0xdd20000`、PE32+。磁盘 Machine 为 `0x8664`，实际加载后的同一进程字段为 `0x0200`，已分别读取确认。直接要求内存 Machine 必为 `0x8664` 会错误拒绝；现接受这两个已观察值，同时继续强制代码哈希和对象类型，未修改原 helper profile/hash。

查询前后通过既有 R21 持久 helper 操作 318 取得活跃地图会话并检查一致。元数据读取只沿经过验证的少量字段，不扫描内存、不暴露任意地址 API。现阶段不需要新操作号或 DLL 协议；保持协议 78。

## 产品继续保留的来源约束

1. 运行时取得的战役绝对路径／地图资源路径，必须对应游戏实际持有的文件；比对本地打开文件与游戏句柄的文件身份，防止同名／替换文件误配。
2. 不读取猜测的候选。若文件写入时间晚于游戏进程启动且无法证明加载版本，则保守拒绝；读取前后检查文件身份、大小、修改时间和会话，保留脚本／字符串表哈希。
3. 战役章节使用元数据中的精确内部路径；独立地图需要证明对应的直接文件。脚本入口／语言歧义、Lua、无可读取脚本均明确提示。
4. 每次检索都必须通过上述验证；仅调查中找到来源不允许后续跳过。R21 主程序、helper 和已有功能当前未改，后续只增加独立任务页的连接入口。
