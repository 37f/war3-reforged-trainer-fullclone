# R25：任务实时完成／失败状态同步

## 目标

用户在“任务与条件”页中查看主线、支线任务时，游戏内任务状态变化后，修改器自动显示“进行中”“已完成”或“已失败”。该功能只读取状态，不执行任务、不触发奖励或剧情。

## 当前基线

R24 的 `QuestAnalysisUI` 根据当前地图脚本构造静态任务报告；其 `QuestAnalysisController` 定期校验地图来源，但不读取任务句柄或运行时任务状态。任务定义已有静态别名 `QuestDefinition.aliases`。当前 native helper 协议为 80，操作号 320–322 已退役，323 用于读取来源策略。R24 的 `IsQuestCompleted` 和 `IsQuestFailed` 原生签名已在 2.0.4.23745 profile 中登记，但产品 helper 尚未读取当前 VM 的任务句柄，也没有运行时状态桥。

旧 R23 运行时调查记录了当前支持构建的 JASS VM/全局变量字段：当前 VM `+0x4878` 为全局名表，名称在节点 `+0x28`，值种类／声明类型在 `+0x30/+0x34`，值在 `+0x38`。这只是调查证据；产品必须按当前进程、当前地图会话重新解析和验证，不得缓存旧绝对地址或扫描整个堆。

## 设计

1. 静态任务报告仍按 R24 方式从地图脚本生成，主线／支线分类依据 `required`，不变。
2. 报告有效且任务页可见时，每秒进行一次只读状态轮询。状态桥只在精确支持的 Warcraft III 2.0.4.23745 x64 构建和当前地图会话校验通过后工作。
3. 运行时读取器只解析当前 JASS 命名空间中、静态任务别名能唯一对应的全局 `quest` 句柄。句柄类型、全局名、当前会话和句柄值均须通过检查；动态数组元素、局部句柄、缺失或重名对象不猜测。
4. helper 在序列化的游戏线程内重新解析当前 VM 和全局句柄，使用已验证的 native 表按名称和签名查询 `IsQuestCompleted` 与 `IsQuestFailed`，按 8 位布尔返回值解释结果。请求只传名称和当前会话令牌，不接收外部函数地址或任务句柄。两个 getter 按任务查询局部绑定，避免将缺少任务接口变成所有原有功能的初始化依赖。
5. UI 在任务列表增加“当前状态”列；详情同时显示状态与最近成功读取时间。状态映射：完成=true、失败=false 显示“已完成”；完成=false、失败=true 显示“已失败”；二者均 false 显示“进行中”；二者同时 true、状态接口不可用或映射不唯一均显示“状态未确认”。
6. 状态读取失败不会抹掉静态任务报告；仅相关状态标为未确认并显示简明原因。地图切换、断开连接、报告过期或关闭任务页后，旧状态立即清空；后台结果按现有 generation/session 身份规则丢弃。
7. 新的只读 helper 操作使用 324，成对协议升到 81。操作 320–323 的语义和 R24 文件保持不变。新版本文件独立命名为 R25-Test；不覆盖 R24，也不发布到 GitHub。

## 边界与失败关闭

- 只为能与静态任务定义唯一关联的普通全局 quest 句柄显示实时状态。
- Lua、自建任务系统、运行时创建且未进入已验证全局别名的任务、数组动态索引、句柄类型不匹配、构建/会话无法确认时，显示“状态未确认”。
- 即使任务分析器能解释脚本中的完成条件，也不能据此伪造实时状态。
- 查询 native 抛出异常或返回不完整结果时不重试写操作、不执行备用状态修改。
- 不修改注册表、任务标志、任务物品、地图资源、存档、胜负状态或奖励。沿用已有的只读来源策略查询；官方基础脚本存在未核对覆盖层时，不把其别名绑定为正式实时状态。

## 验收

- 状态变化可在轮询后出现在对应的主线／支线行；静态任务说明和分类仍可查看。
- 明确证明无任何任务 setter/触发器调用路径新增。
- 失去唯一映射、切图、重连、helper 异常时不显示旧状态或误报完成／失败。
- 需要用户在一个可安全推进的地图中实测至少一个完成任务和一个失败任务；仅源代码／离线包核对不算游戏实测。
