# 战役与所选章节的自定义对象 ID 目录

日期：2026-10-24。状态：设计待用户确认，尚未开始产品实现。

## 需求和已选方案

用户希望在修改器中查看自定义战役作者加入的物品、技能和单位 ID，以及对应名称。现有三个 ID 页使用离线通用目录，不包含当前战役或地图自定义对象。

用户已选择“只读解析战役文件和当前章节”。这里的“当前章节”由用户在修改器中选择；第一版不自动判断游戏实际载入哪一章，也不暗示所选文件已经与游戏进程核对。

这是一项有独立解析器、归并逻辑及界面接入的功能扩展。先把文件检测做可靠，再接到现有三个 ID 页。

## 方案比较

1. **已选：文件检测。** 选择 `.w3n`，从战役清单中选择章节，读取战役公共对象数据及该章节的地图对象数据。可以看到尚未生成到地图中的定义，不依赖已选单位或 native 调用。
2. **暂缓：从游戏自动识别章节并枚举对象。** 用户少一次选择，但当前代码没有章节路径识别或完整对象类型枚举接口；扫描已生成单位、背包及技能不能证明覆盖完整。

不把所有章节的定义混成一个无来源的总目录；同一 rawcode 可能在不同章节代表不同内容。

## 使用流程和界面

在现有“物品 ID”“技能 ID”“单位 ID”页增加目录来源切换：`通用目录` / `战役与所选章节`。通用目录保留现有搜索、排序和双击复制 ID 的行为。

自定义目录提供：

- “选择战役”按钮与所选文件名称/路径。
- 章节下拉框，优先显示战役清单中的章节标题，同时保留内部地图路径。
- “检测自定义对象”按钮及状态信息；检测结果由三个 ID 页共享，切换页不重复扫描。
- 结果列：ID、名称、基础 ID、对象类型（新增 / 原版改动）、数据来源（战役公共 / 所选章节 / 两层共同定义）。
- 沿用搜索和复制 ID，搜索支持 ID、名称、基础 ID 和来源。
- 显示所选章节和物品/技能/单位计数，以及“完整读取”“部分读取”或“检测失败”的实际状态。

首次未选择文件、已选择但未检测、正在检测、成功、部分成功、失败各有独立状态。切换战役或章节后立即清空上一章的结果；异步旧任务返回时不能覆盖新选择。第一版只在显式点击时检测，不定时扫描。

新增控件接入现有语言切换，原有中文/英文通用目录照常使用。自定义名称保持作者原文，不自行翻译或制造英文名。

## 读取边界

读取 `.w3n` 中的战役清单、字符串表、单位/物品/技能对象文件，以及用户所选章节的内部地图和对应文件：

- 战役层：`war3campaign.w3f`、`war3campaign.wts`、`war3campaign.w3u/.w3t/.w3a`。
- 章节层：`war3map.wts`、`war3map.w3u/.w3t/.w3a`。

用战役清单定位章节，不依赖硬编码章节名。可用 `(listfile)` 补充可枚举地图路径；清单/列表不完整时明确提示，不用猜测路径伪装完整枚举。独立地图选择不属于第一版必需范围。

用经过来源与位数核对的 StormLib 只读接口读取 MPQ；只封装打开、查询、读取和关闭，禁止引入新增、删除、保存接口。工具必须独立随修改器打包，不依赖本机某游戏目录下碰巧存在的 DLL，不向游戏注入新的解析器。选择官方上游可复现构建或核验过的官方二进制，记录版本、来源、SHA-256 与许可证；第三方解析依赖与现有 native helper 分开。

外层文件及内层章节只读。若打开游戏造成文件占用，只能读取成功或提示占用；必要时在修改器工作目录制作只读分析用副本，绝不移动、改名或解锁原文件。临时章节文件使用系统生成名称，不直接拼接档案内路径，以防路径越界；任务完成关闭句柄并清理自己的临时文件。

不全量导出战役的声音、模型、贴图或脚本；不执行地图脚本、外部程序或归档内内容。后台任务只做文件解析，Tk 控件由主线程更新。为档案条目大小、对象/字段数量、字符串长度、任务时间和结果数量设置合理上限，超限停止并说明限制，不静默截断成成功。

## 对象格式、名称与归并

单独实现可测试的只读对象数据解析模块，按版本处理头部、原版改动表和自定义对象表；技能记录的等级/数据指针字段与单位、物品格式分开处理。检查剩余长度、字段类型、数量和记录结束标记。明确列出实际支持的版本；不认识的版本报告不支持，不能套用其他版本硬读。

保留四字节 rawcode 的大小写和原始值。新增对象显示其新 ID 和基础 ID；原版改动显示原 ID，不能被算作新增对象。不可安全显示或用于现有输入框的 ID 必须标示，不用替换字符生成假 ID。

名称读取规则：

1. 先解析字段所属层的名称与 `TRIGSTR_*`。战役字段用战役 WTS，章节字段用章节 WTS；不能因为编号一样就跨层误配。
2. 相同 ID 在章节中有字段改动时，以章节显式字段覆盖战役对应字段；未改动的名称仍沿用战役定义。不是无条件用整条章节记录替换战役记录。
3. 自定义对象没有显式名称时，可沿基础对象定义继承，再以已知通用目录名作标记清楚的回退。递归继承要检测循环与缺失基础对象。
4. 字符串无法解析、文本编码不明确或名称缺失时保留可读证据（例如未解析的 `TRIGSTR_123`），显示缺失原因，不猜名称。显示名可去除已识别的魔兽颜色控制码，同时保留原始名称供诊断。

同一章节内的有效条目按对象类别与 rawcode 去重，保留战役/章节来源；无法可靠合并的 ID 冲突标明冲突，不能随意挑一个并表示成功。章节名称也按相应字符串表解析。每个来源文件单独记录读取状态，区分“文件确实不存在（该层没有此类定义）”与“存在但读取/解析失败”。某一类损坏不丢弃其他已成功解析类别，但整体必须显示部分读取及失败详情。

## 不改动的范围

- 游戏进程扫描、读取方式、native 表、hash、操作号和 helper 协议保持原样。
- 既有复制、归属、队伍监视、快捷键等扩展行为保持原样。
- 不修改战役、地图、存档或对象数据；不自动调用创建单位、添加物品、添加技能。
- 不承诺列出仅由运行时系统改名或非标准外部工具生成、且不在支持文件格式中的定义。
- 检测到定义不等于验证其可在任意章节使用或执行成功；界面只声称读取所选文件定义。
- 不在本次实现中自动上传 GitHub。此前 R19.3-Test 上传请求暂缓，待本功能范围明确后再按用户指示发布。

## 实现者可自行决定的细节

以下是实现建议，不冒充用户已经指定：模块文件名、内部数据类、控件具体排布、缓存和上限数值、官方 StormLib 构建方式、版本号及单独测试 EXE 文件名。保持少量独立模块，避免大规模重构主程序。第一版优先内存结果，不建立跨战役持久化数据库。

## 验收和交付

先用小型合成样本覆盖物品、技能、单位的新增/原版改动、空表、WTS、版本差异、继承、章节覆盖、同号不同层字符串、冲突、损坏和上限。再用一个真实战役与指定章节只读核对，记录源文件检测前后的 SHA-256，核对已知的对象 ID/名称。

界面检查选择文件、章节、状态、搜索、双击复制、三个页共享结果、切换章节清理、异步旧结果隔离、语言切换，以及不连接游戏时仍可检测。回归现有通用目录测试；构建新的单独命名 EXE，核对冻结包内解析模块和档案依赖均存在。源码测试、实际档案解析、界面检查和游戏内功能验证分别报告，不互相代替。

交付独立测试 EXE、相应源码和中文使用说明，保留旧版。真实战役路径和测试章节尚未由用户给出，可在实现期间补充；缺少样本时不能把合成测试宣称为真实战役验收。
