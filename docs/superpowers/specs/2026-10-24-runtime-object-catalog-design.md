# R21：直接检索游戏当前地图的对象 ID

日期：2026-10-24。状态：用户已确认设计；已实施目录/helper/UI，正在进行最终审阅及 R21 打包验证。

## 用户目标与范围

用户希望打开自定义战役章节后，在修改器内直接检索当前地图的单位、物品、技能 ID 和名称，无需选择战役文件、章节，也无需先选中某个单位。已有 R20 的通用目录及文件检测继续可用。

结合最初的“作者加入自定义物品、技能和单位”需求，本次“全部”指当前已加载地图对象定义中的新增对象和原版改动记录，包括尚未在场上生成的定义；不是只扫描场上单位、背包和已学技能。未被地图修改的原版对象仍在已有“通用目录”中，不能把离线通用目录称作当前地图实际定义。界面明确使用“当前地图定义”，分别报告三个类别的定义数。

当前地图继承并可用的战役公共对象也必须包含，即使当前章节没有再次修改它。本轮补充逐项核对了《亡灵骑士》中只存在于战役公共层的 51 个单位、14 个物品、25 个技能，运行时均包含。正式 helper 实现仍须重复这个验收，并测试章节覆盖公共同号对象的情况。其他样本若当前原始数组未包含公共对象，要继续定位有效的运行时公共层并按游戏覆盖关系归并，不能用同一数组的枚举计数自证完整，也不能自动读猜测的战役路径弥补。

本次不建立跨章节数据库，不新增修改对象或直接执行 ID 的入口，不列出所有其他章节的定义，不扩展到装饰物、可破坏物、魔法效果、科技等其他对象类别。读取到定义不等于证明该对象可安全创建、施放或用于其他章节。

## 方案比较与已选方向

1. **已选：读取当前地图运行时的完整定义层。** 用户已选择“在修改器里直接检索当前地图全部 ID，无需选战役文件”。只读探测已找到三类原始定义数组，能覆盖界面缓存未载入的技能。产品接入现有持久 native helper，在游戏线程取得当前上下文和有界快照，沿用现有连接、互斥和错误通道。需要新增目录查询、协议与版本校验；不复制任何旧写入处理器。
2. **保留作为独立来源：R20 文件检测。** 能离线解析选定战役和章节，适合对照验证，但不能满足无需选择文件的目标；不会悄悄以猜测的章节文件替代运行时读取。
3. **不采用：场上实例或界面缓存枚举。** 当前章节技能缓存仅含 33 条定义中的 8 条，不能声称“全部”。探测用的私有内存扫描也不进入产品：扫描约 1.4–1.7 GiB 只用于定位证据，不能变成每次点击的正式流程。

接入持久 helper、手动刷新、保留另外两个来源、上限及分页细节是实现建议，并非用户另行指定的操作细节。

## 当前实测证据及其边界

目标游戏为 Warcraft III 2.0.4.23745，EXE SHA-256 为 `682c12552ca05e43c5fed2340ea132d3b06fe068e676db7d1f5623d8d4633229`。用户指定《亡灵骑士》第一章，文件参考定位为 `亡灵骑士.w3n / necroknight1.w3x / 第一章 / 复仇`。

两个不同游戏进程中重新定位到相同结构。第二次核对：

| 类别 | 运行时定义数 | 文件定义数 | 缺失/多余 ID | 显式名称核对一致 |
| --- | ---: | ---: | --- | ---: |
| 单位 | 64（23 原版改动、41 新增） | 64 | 0 / 0 | 35 |
| 物品 | 14（全部新增） | 14 | 0 / 0 | 13 |
| 技能 | 33（1 原版改动、32 新增） | 33 | 0 / 0 | 24 |
| 合计 | 111 | 111 | 0 / 0 | 72 |

其余 39 条没有显式名称，仍须在产品中处理继承及标明来源的回退。观察到探测早期字段曾为 `TRIGSTR_*`，稍后游戏自身将相同字段解析为文本；不能假定任意读取时刻都已完成解析。未解析字符串必须显示原编号与原因，不猜名称或跨章节套用字符串表。

公共层单独对照：本战役有 51/14/25 条公共单位/物品/技能定义；当前章节本身分别有 13/0/8 条，三个类别均没有与公共层重复的 ID。公共层专属共 90 条在运行时全部存在。因此本章 111 条包含公共层 90 条和章节 21 条。证据为 `session-33020/public-layers.json`；目前没有以此证明章节同号覆盖的优先关系。

这一轮只使用 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`，没有目标进程写入、远程调用、DLL 加载或快捷键操作。参照战役的 SHA-256 和修改时间在文件对照前后不变。已运行既有解析相关回归测试，34 项通过。

**目前未证明：** 其他地图/章节、存档载入、返回菜单后再入图、地图生命周期标识、生产 helper 查询的实际表现、39 条继承名称的运行时取值、不同游戏版本。证据为只读探测，不是 R21 成品验收。

## 数据路径和最小改动

现有三个 ID 页共享一个新增的“当前地图”选择状态；不重构主程序、原读取入口或旧扩展功能。

1. 在已验证游戏构建上，由 helper 游戏线程调用现有上下文入口取得对象数据上下文。只读上下文中的三类管理器指针，不调用会在未初始化时创建管理器的 getter。
2. 校验类型、vtable/代码特征、指针范围和表头，再枚举原版改动数组及新增数组。返回 rawcode、基础 rawcode、对象类型、名称原值、名称解析状态。保持 rawcode 原始四字节和大小写。
3. 查询按小批次执行，后台接收不可变的本地结果。每批携带请求号及地图会话标识，完成所有批次且前后校验一致才发布。禁止传入任意地址供界面读写。
4. Python 独立模块负责协议解码、验证、继承、通用目录回退和结果状态；复用 R20 已验证的 rawcode 展示、颜色码去除及复制限制。运行时来源标为“当前地图”，不捏造“战役公共/章节”来源。
5. 现有 native 名称、签名、hash 及旧操作号含义保持原样。新增目录操作使用未占用编号，升级配套 helper 协议与冻结包验证。新 EXE 连接到旧 helper 时明确提示版本不一致，不继续执行不兼容请求，也不悄悄卸载旧 helper。

只读指不改变单位、玩家、对象字段或地图内容；helper 自有的查询缓冲区与通信状态可按现有机制分配、写入和释放。依赖已有持久 helper，不新增独立扫描服务或解析器 DLL。

## 名称和完整性

- 显式 `unam` / `anam` 优先；保留原文，去除可识别颜色控制码用于显示。
- 没有显式名称时，先在同类当前地图定义中沿基础 ID 继承；检测循环及深度上限。最后可回退现有通用目录，并明确标注“名称回退到通用目录”。不将回退称为运行时实测名称。
- `TRIGSTR_*` 尚未解析、编码异常、基础对象缺失、同号冲突都保留 ID 并显示原因；名称不完整时整体为“部分读取”，但有效的 ID 仍可检索。
- 保留原始字段的对象集合 key，不把多个集合的名称默默压成首项。若存在不同名称，只有验证当前生效集合选择规则后才能给出唯一运行时名称；尚不能确定时显示“名称存在多个候选”，在详情列出集合 key 与候选，整体标为部分读取。相同名称可去重。名称歧义不能用通用目录覆盖掉，ID 无冲突时仍可复制。
- ID 枚举完整和名称解析完整分别统计。空表只有在上下文有效、三类读取均成功且计数确实为零时才算“无此类自定义定义”；菜单、加载中、缺少管理器和不支持版本不能显示为空表成功。
- 非显示 ASCII、歧义十六进制输入（例如 `0xAB`）或冲突 ID 沿用 R20 的禁复制处理；不替换字节伪造有效 ID。

## 会话、换图和线程边界

产品不保存跨进程的绝对地址；不把探测脚本中某次运行的地址写入产品。

连接/断开进程、更换 PID 或进程创建时间、读取来源改变、开始新检测时立即清空旧结果及复制状态。新请求拥有独立 generation；旧任务成功返回也不能覆盖新状态。三个 ID 页共享结果，不为每个页重复读取。

当前地图数据入口、定义数组指针/计数和 ID 摘要必须在批次前后核对。实现阶段还必须通过菜单、重新载入及换图实验找到并验证地图生命周期标识；不能只用 PID、地图名字或一个可能重用的内存地址。无法确定本次结果属于同一地图会话时，丢弃该批次并提示重新检测。

结果标明“检测时快照”及读取时间。只有当前地图来源可见时，才以轻量查询检查地图会话是否变化；变化或校验失败立即清空结果、禁用复制并提示重新检测。不会持续全量扫描。若生命周期标识尚不能可靠验证，R21 发布受阻，不以“只需手动重刷”绕过旧结果误用于新地图的问题。

helper 对共享快照、超时和退出负责释放；Python 工作者不访问 Tk，主线程只处理已验证结果。所有 helper 请求使用现有串行通道，与队伍监视、选中单位读取等操作不能并发覆盖命令缓冲区。

## 有界读取与失败处理

沿用项目的 SEH/指针可读性检查，字段解析设数量、容量、字节数、字符串、继承深度及时间上限。建议整次最多 100000 条对象、32 MiB 返回数据、每个名称最多 64 KiB，单批工作量须经过实际计时调整；超限报“部分读取/超限”，禁止截断后表示成功。

禁止从异常现场继续猜指针、遍历环形链、执行未知函数或写入游戏修复数据。查询取消、加载中、菜单、进程退出、旧协议、不支持构建、名字缺失分别给出可理解的状态，后台监视不循环弹窗。需要用户重启才能更换 helper 时，只提示并等待，不擅自关闭游戏。

## 界面行为

三个 ID 页在已有“通用目录 / 战役与所选章节”旁增加“当前地图”。选择后显示“读取当前地图 ID”、共享状态和读取详情；文件选择与章节控件只服务文件来源。现有搜索、排序、双击复制沿用。

状态至少区分未连接、尚未检测、正在检测、完整读取、部分读取、未进入地图、版本不支持、会话已变化、失败。计数、来源和快照时间始终可见。中文/英文切换同步新增控件，自定义名称不自动翻译。通过检测不自动切换复制归属，也不创建单位、技能或物品。

## 验证和交付标准

1. **纯解析与状态测试：** 原版改动/新增/空表、四字节大小写、越界/截断/无效指针、循环/重复、继承、长字符串、未解析 TRIGSTR、同号不同类别、旧任务返回、地图令牌变化、取消/超时、协议不一致。不写只复述实现的测试。
2. **helper 检查：** 新处理器只读目标数据；不调用懒创建 getter 或旧写入操作；保护旧 handler、native 表和 hash；在当前编译工具链编译并做已有协议/打包一致性测试。
3. **只读游戏实测：** 当前《亡灵骑士》第一章对照 64/14/33 ID、已知名称；至少再选一个不同定义集合的章节/地图验证换图、读档、菜单、退出及旧快照清理。另须覆盖一个含战役公共层专属对象的样本，核对该对象在章节未再次修改时仍被列出，以及章节覆盖时同号对象正确生效；这不是可省略的“全部”验收项。多集合不同名样本至少验证不会任取首项宣称唯一名称。未获得样本或用户没有方便换图时如实标记未验收，不改用户进度。
4. **界面与冻结包：** 三个来源可切换，三个页共享结果，搜索复制和中英文可用；冻结 EXE 内含新模块和匹配 helper。运行新目录查询时旧队伍监视和普通读取不被破坏。
5. **交付：** 独立 R21 测试 EXE、匹配源码 ZIP、中文说明与校验文件，保留 R20。报告分别区分单元测试、文件对照、界面与游戏实测。本轮不自动发布 GitHub。
