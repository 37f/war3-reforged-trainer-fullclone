# Warcraft III Legacy 修改器 v0.2.0-Test 使用说明

适配目录：`E:\Games\Warcraft III (Legacy)`；实际主程序版本 **1.29.2.9231（x86）**。安装记录中的1.29.2.9232-legacy-tft以实际EXE为准。游戏EXE SHA-256为 `3f2ed0120d80578bf07e4423296dade1adfb959d59a2d20a7584224559570eed`。修改器外壳为Windows x64，内部助手为x86，无需安装Python。不同游戏文件或补丁会拒绝连接。

## 启动

1. 保存进度，关闭第一版及其他修改器，从上述Legacy目录启动游戏并进入地图。
2. 打开 `War3LegacyTrainer-v0.2.0-Test.exe`，点击“连接 Legacy”。连接只读取当前资源及选中单位。
3. 需要快捷键时勾选顶部“启用游戏内快捷键”，回到游戏窗口使用；默认关闭，只有指定游戏窗口处于前台才执行。
4. 选中单位后可直接操作，无需每次先按F5。程序会自动重新读取选择，再核对句柄/类型/归属。
5. 换图、读档、返回菜单后重新连接。两个版本不能同时连接同一游戏进程。

## 快捷键

| 快捷键 | 功能 |
| --- | --- |
| F5 | 读取资源和选中单位 |
| Ctrl+空格 | 选中活单位生命魔法全满；不复活 |
| Ctrl+Q | 默认英雄每次升1级；勾选自定义后按输入值设置 |
| Alt+Q | 默认永久三围各加2；勾选自定义后按三个输入值设置 |
| Ctrl+L | 给资源列表选中玩家增加金币木材，数量见输入框 |
| Ctrl+B | 每个选中单位复制1个，服从复制归属选择 |
| Ctrl+A | 每个选中单位复制1个，固定给自己 |
| Ctrl+N | 每个选中单位复制指定数量，服从归属选择，默认10 |
| Ctrl+U+8 | 替换为输入的4位单位ID；默认zhyd，使用主键盘数字8 |

按住快捷键不会自动连发。操作期间不排队重放；按钮和快捷键共用后端。等级与三围自定义输入框默认灰色，勾选才开放，非英雄跳过等级/三围操作。

## 玩家资源

在“玩家资源”选择玩家行，填写金币、木材、已用人口或人口上限后设置；也可以增加金币木材。不会锁定数值，游戏和地图脚本仍可更新。普通未启用玩家不可写入。

本引擎兼容旧地图中立编号：旧图脚本玩家13～16对应内部中立25～28，新图可能显示25～28。程序按本机Player/GetPlayerId实际映射去重并标注中立名称，不固定套用25/28。当前测试旧图返回24个唯一脚本槽位。

## 复制单位、大量复制及归属

打开第三个标签“复制与替换”，归属可选“给自己”“给选中单位所属玩家”“给指定玩家”。指定玩家下拉包括本图普通玩家及中立槽位。Ctrl+A始终给自己，Ctrl+B/Ctrl+N服从面板选择。

“复制单位”每个源单位创建1个；“大量复制”的数字是**每个源单位创建几个**。支持多选，单项数量1～200，一次总创建数不能超过200。副本在源单位附近分散创建，直接使用最终归属，不会先混入我方再转交。

已接入复制：单位类型、英雄经验与等级、永久三围、可用技能点、可枚举普通技能及等级、当前/最大生命魔法、暂停和经验暂停状态；六格物理背包的物品类型、所在格、数量、生命、无敌及可出售标记。副本获得**新的物品实例**，源单位和原物品保留。物品附带技能由新物品重建，避免重复加成。

永久三围不含物品临时加成。最大生命/魔法接口接受整数，有小数时取整并提示。死亡单位不复制/替换。技能链有数量及循环边界，超限或技能/物品读回不符会停止并说明。

## 替换单位

输入4位ASCII字母或数字单位ID（区分大小写），点击“替换单位”或按Ctrl+U+8。默认 `zhyd`。ID须存在于当前地图能创建的定义；未知ID会拒绝并保留原单位。

替换保留源玩家、朝向、原位置附近的合法落点、生命魔法与暂停状态。背包的**原物品实例**按格转移，目标无背包时增加背包能力。英雄替换为英雄时传递经验、等级、永久三围、技能点及经验暂停状态；目标使用新单位类型自己的技能模板。英雄变成普通单位时英雄字段不适用，并显示提示。

新单位、物品及状态核对后，最后移除原单位。地图中引用旧单位的剧情、触发器、变量、编组不会自动改为新单位；关键任务单位建议先存档。创建单位、获得物品等地图事件仍会执行。

## 边界和异常处理

- 本版包含第一版基础功能和上述第二版功能，没有移植Reforged的全部扩展。
- 不复制英雄专有名、显示名、脚本自定义数据、触发器绑定、技能冷却、临时BUFF持续时间、任意伤害/护甲实例字段或脚本模拟的额外背包。
- 不保证每张地图的特殊技能均可复制。无法经本版接口确认的对象会停止并报明原因；替换单位保留新类型的技能模板。
- 物品转移部分发生后再失败时，保留携带原物品的新单位，可能留下两个单位供核对；无法通用回滚地图脚本外部副作用。
- 部分操作可能生效时暂停后续写入，先F5核对；超时/访问异常不自动重放，核对游戏后重新连接。
- 错误记录在 `%LOCALAPPDATA%\War3LegacyTrainer\last-error.json`。不安装服务、不改注册表、不修改原游戏文件。
- 暂无独立地图代次识别，世界地址和句柄可能被复用；换图/读档后必须重新连接。

## 验证和构建

在用户授权任意操作的当前Legacy测试地图，使用正式助手验证了单个复制、自定义英雄/物品状态复制、指定普通玩家和中立敌对/被动、源归属、多选大量复制、zhyd和Hpal替换、原物品实例转移、未知ID及未启用玩家拒绝。原始Ekee的等级、永久三围、最大生命魔法与背包身份核对保留。

8项Python测试、361项基础核心断言、117项复制核心断言及x86异常夹具通过；这些为隔离测试，不连接游戏。UI离线检查覆盖三页控件与默认值；冻结程序内嵌代码/组件逐项核对。快捷键分发通过模拟前台/按键状态检查，尚未逐个实按验收所有快捷键。详见随包VERIFICATION.json。

源码构建需要Windows x64 Python3.12、Tk、PyInstaller、pefile及LLVM-MinGW i686 clang：

```powershell
python build.py --compiler "你的LLVM-MinGW目录\bin\i686-w64-mingw32-clang.exe"
```

extract_profile.py仅从指定游戏读取签名/布局，不执行游戏。live_v2_acceptance.py是授权测试地图工具，会创建/替换对象，不要在普通存档运行。测试专用入口只编入单独测试DLL，正式EXE不含此入口。第一版EXE和源码包各自保留。
